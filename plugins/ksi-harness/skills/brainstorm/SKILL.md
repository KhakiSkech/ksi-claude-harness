# Brainstorm — 발산 → 수렴

## 절차

1. **문제 정의** — 무엇을 풀려는지, 제약과 성공 기준을 한 줄로 고정한다.
2. **발산** — 서로 다른 각도에서 최소 3~5개 접근을 낸다.
   - 예: MVP-우선 / 리스크-우선 / 사용자-우선 / 단순함-우선 / 비관습적 한 방
   - **각도가 여럿이고 서로 독립적이면**(=독립 병렬 단위 — 위임 실익) workflow로 각 각도를 병렬 fan-out 한다. 각도가 소수면 메인이 직접 발산하는 게 더 싸다 — 크기가 아니라 병렬성이 기준. 발산·조사 워커는 싼 tier(haiku/sonnet + effort 명시), 수렴·trade-off 판정은 메인 — **모델 배치 규칙은 CLAUDE.md '모델 배치' 참조**(여기 재기술 안 함).
3. **군집화** — 비슷한 아이디어를 묶고 중복을 제거한다.
4. **비교** — 표로 trade-off 정리: 장점 / 단점 / 비용 / 리스크 / 적합 상황.
5. **수렴** — 1개 추천 + 근거. 차순위 안에서 살릴 아이디어가 있으면 접목한다.
   - **발산 축이 시각/레이아웃/디자인이면** 수렴 산출물을 텍스트 표가 아니라 **시안 비교 Artifact**로 낸다(매체 SSOT=CLAUDE.md 작업방식). 레이아웃·정보구조 trade-off는 픽셀로 봐야 판단된다.
6. **다음 단계 (핸드오프)** — 추천안을 실행하려면 무엇부터인지 제시. 새 기능·대형 변경이면 `/deep-interview`로 spec 확정 후 Plan/구현, 단순하면 바로 Plan/구현으로 넘긴다.

## 원칙

- 발산 단계에선 비판 금지 — 일단 넓게. 수렴 단계에서 냉정하게 친다.
- 추천은 분명하게. **"둘 다 좋다"로 끝내지 않는다.**
