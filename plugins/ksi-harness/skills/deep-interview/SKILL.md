# Deep Interview — 착수 전 의도 확정

큰 작업을 추측으로 시작하지 않는다. 의도를 좁힌 뒤에만 구현/계획에 들어간다.
목적은 심문이 아니라 **재작업 방지**다.

## 절차

1. **요청 재진술** — 이해한 목표를 한두 문장으로 되돌려 말한다. ("원하시는 건 X로 보입니다, 맞나요?")
2. **모호점 식별** — 두 갈래 이상으로 해석되는 지점, 숨은 가정, 빠진 정보를 나열한다.
3. **타깃 질문 — 백지 질문 금지(recommendation before question)** — `AskUserQuestion`으로 핵심 질문을 **묶어서** 던지되, 각 질문에 **합리적 추천안을 첫 옵션으로** 제시한다("어떻게 할까요?"가 아니라 "B를 권장합니다 — 이유는 X. 확정할까요?"). 한 번에 하나씩 캐묻지 않는다.
   - 스코프 경계(포함/제외), 제약(성능·보안·기한·"무료 도구만"), 성공 기준, non-goals.
4. **엣지·리스크 점검** — 되돌리기 어려운 부분(삭제·배포·마이그레이션·비밀 변경), 기존 시스템과의 충돌을 확인한다.
5. **합의된 spec 산출** — 목표 / 범위 / 비범위 / 제약 / 수용 기준(acceptance criteria)을 짧게 정리해 확인받는다.
6. **그 다음에만 진행** — 합의된 spec에 독립 병렬 단위가 여럿이면 workflow로 fan-out, 설계가 더 필요하면 `Plan`으로 — 크기가 아니라 병렬성·위임 실익이 기준.

## 원칙

- 답이 명백한 건 묻지 말고 합리적 기본값으로 채운 뒤 "이렇게 가정했다"고 밝힌다. **과한 질문도 비용이다.**
- 모르면 추측해서 밀지 말 것. 핵심 모호점만 골라 묻는다.
- **대상 혼동**(파인튜닝/평가 대상 모델 vs 실행 에이전트 모델 등)이 비싼 오해다 — 대상이 헷갈릴 수 있으면 반드시 확인.
- **UI/화면 신규 기능이면** 모호하지 않아도 합의 spec에 **UX 축을 포함**한다(목록 = CLAUDE.md 작업방식의 UX목표 5축 = `/ui-audit` 측정 기준). UX 목표를 안 적으면 나중 검증이 '잘 구성됐나'만 통과시킨다.
- **멀티액터/금전/평판/권한 기능이면** 합의 spec에 **어뷰징 축을 포함**한다(파이프라인이 '만들 것'에만 정렬돼 '금지돼야 할 것'을 놓치는 사각 교정) — 등장 actor 열거 + *분리돼야 할 역할 쌍*과 무결성 불변식을 적는다(4 어뷰징클래스·음성 케이스 self/cross/replay/state-change-after = CLAUDE.md 'green≠금지' SSOT = `/codebase-audit` 어뷰징 렌즈 측정 기준). **단일 actor·단일 CRUD면 생략**(과한 질문도 비용).
