# Deep Interview — 착수 전 의도 확정

큰 작업을 추측으로 시작하지 않는다. 의도를 좁힌 뒤에만 구현/계획에 들어간다.
목적은 심문이 아니라 **재작업 방지**다.

## 절차

1. **요청 재진술** — 이해한 목표를 한두 문장으로 되돌려 말한다. ("원하시는 건 X로 보입니다, 맞나요?")
2. **모호점 식별** — 두 갈래 이상으로 해석되는 지점, 숨은 가정, 빠진 정보를 나열한다.
3. **타깃 질문** — `AskUserQuestion`으로 핵심 질문을 **묶어서** 던진다. 한 번에 하나씩 캐묻지 않는다.
   - 스코프 경계(포함/제외), 제약(성능·보안·기한·"무료 도구만"), 성공 기준, non-goals.
4. **엣지·리스크 점검** — 되돌리기 어려운 부분(삭제·배포·마이그레이션·비밀 변경), 기존 시스템과의 충돌을 확인한다.
5. **합의된 spec 산출** — 목표 / 범위 / 비범위 / 제약 / 수용 기준(acceptance criteria)을 짧게 정리해 확인받는다.
6. **그 다음에만 진행** — 작업이 크면 여기서 바로 workflow나 `Plan`으로 넘긴다.

## 원칙

- 답이 명백한 건 묻지 말고 합리적 기본값으로 채운 뒤 "이렇게 가정했다"고 밝힌다. **과한 질문도 비용이다.**
- 모르면 추측해서 밀지 말 것. 핵심 모호점만 골라 묻는다.
- 과거 "파인튜닝 대상 모델 ↔ Claude 동작 모델" 같은 **대상 혼동**이 가장 비싼 오해다. 대상이 헷갈릴 수 있으면 반드시 확인.
